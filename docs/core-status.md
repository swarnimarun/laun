# Core implementation and acceptance status

Updated 2026-11-14. **All requested core features are implemented and qualified for local testing.** The requested end state is the complete Bun/TypeScript app: named mowers, durable server threads, a director and delegated crew, local/VPS execution yards, central permissions/auth/MCP, Telegram and a presentable browser interface. Rust and additional runtime engines remain future directions.

The original detailed plan is split into [control](design/01-control-plane.md), [permissions](design/02-permissions.md), [runtime](design/03-runtime.md) and [product/operations](design/04-product-operations.md). Each section received [independent review](design/reviews.md). The table below describes implemented behavior and its actual acceptance evidence; it does not turn every possible future feature into a completion requirement.

## Final local acceptance record

Counts are separate snapshots and are not added together.

- Full frozen source suite: **941 passed, one intentional opt-in Goose skip, zero failures; 4,519 assertions across 84 files**.
- TypeScript build passed. Browser: **22 workflow groups**, zero page errors, with actual Pi Durable and explicitly scripted test models.
- CLI focused snapshot: **173 passed / 907 assertions**. Telegram bridge: **41 passed / 181 assertions**, using actual grammY with local fake Telegram APIs.
- Fresh controller archive: verified receiver, frozen Bun install, full build, actual no-model owner/durable/inference contract and identical post-build retry passed, preserving source inodes.
- Portable CLI: compiled development artifact works outside the checkout, its source manifest matches, a fresh 297-file worker source installs offline and typechecks, and checked private runtime values are absent from the binary.
- Actual final controller image: **d8bee16c5154b6c2ff8a9e2beee3145a91b14631754529cb82312f7994a7b2f3**, with 41 critical current-source hashes matched. It passes the exact disposable no-network/read-only installer contract.
- The same image passes the complete isolated HTTP/Pi flow: six scripted model calls equal six central admissions; initial ledger head 50; mTLS, actual resources, read/write/process, filesystem/network denials, credential exclusion, restart without replay, complete local cache-loss recovery, separate host approval, removal of one owned sandbox plus one managed path and a removed-input retry returning 410.
- The same image also passes the committed release demo qualifier: bad-key 401, cross-owner 404, stable owner/input receipts across restart, durable Pi history, exactly two central inference admissions and no full/half credentials in thread artifacts.
- The sandbox image was rebuilt from current source and matches **d9ed3f26cd68cf7cafdad6a9c8346100fc57c54dab7e32bd0bb11e83e72570dc**. The real builder excludes all 64 synthetic private-state sentinels.

Pinned upstream versions were rechecked against primary release pages on 2026-11-14: [Pi 1.5.2](https://github.com/earendil-works/pi/releases) and [OpenShell 0.1.8](https://github.com/NVIDIA/OpenShell/releases/tag/v0.1.8).

## Deployment boundaries

The requested core app is ready to test locally. No actual external VPS was supplied or modified, no real Telegram messages were sent, and no image, binary or workflow was published/triggered. Real bot/private/topic delivery and a selected VPS's installation/network/certificates remain environment-specific qualification. Local fake transport is not described as live Telegram proof.

The compiled artifact is an unpublished development candidate, version 0.2.0-dev. Release CI now pins Bun/Ubuntu and gates publication on source, browser, context and packaged durability checks; the workflow itself has not been run remotely during this work.

Supported plugins are HTTP MCP tools with server credential references. Arbitrary executable plugins, additional chat services/runtime engines, general per-command semantic policy, universal external-effect exactly-once delivery, a Rust port and Kubernetes/webhooks are outside this core scope.

Start the local app with `bun run dev:app --demo`; its generated credential is in the private, ignored `.laun-local/access.json` file. The [demo guide](demos.md) also provides disposable scenarios and reproducible screenshots. Real operation requires configured controller model credentials and either explicitly trusted local execution or a qualified OpenShell yard.
